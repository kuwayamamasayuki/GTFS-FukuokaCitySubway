# 地上出入口モデル（stops.txt の location_type=2）— Issue #50

## 背景と目的

`stops.txt` には従来、駅（`location_type=1`）とホーム（`location_type=0`）しか無かった。
地下鉄は地上出入口が多数あり、出入口を `location_type=2` / `parent_station=駅` の stop として
追加すると、経路検索エンジンが「最寄り出入口 ↔ 目的地」の徒歩を含めて案内でき、
ドアtoドアの正確な経路案内ができる（`pathways.txt` と組み合わせると効果大）。

## データモデル

| 列 | 値 |
|---|---|
| `stop_id` | `{親駅id}_e{連番}`（例 `1_e1`, `11_e3`, `37_e5`）。既存ホーム `_1`/`_2` と衝突しない |
| `stop_name` | 「駅名＋公式出入口名」（例 `姪浜北出口`, `博多西1出入口`）。福岡空港のみ採録名そのまま |
| `stop_lat` / `stop_lon` | **推定座標**（後述）。福岡空港のみ実測値 |
| `zone_id` | 空（出入口は運賃ゾーンを持たない） |
| `location_type` | `2` |
| `parent_station` | 親駅（`location_type=1`）の `stop_id` |
| `wheelchair_boarding` | `0`（情報なし） |

実装は `scripts/seed_reference.py`:
- `STATION_ENTRANCES`（親駅id → `[(ラベル, 方角語), ...]`）と福岡空港用 `AIRPORT_ENTRANCES`。
- `transform_stops` 末尾で各駅へ出入口行を**冪等**に追加（既存 `stop_id` があればスキップ）。
- 座標は `_estimate_entrance_coord` で算出。
- `reference_gtfs/stops.txt` が真実のソース。`make build` / `make publish` で `dist/` と
  `dist/FukuokaCitySubway.zip` に反映される。

## 出入口名の出典

各駅ページ（`https://subway.city.fukuoka.lg.jp/eki/stations/<slug>.php`）の
**駅立体図**（`img/map_<slug>.jpg`）を目視し、地上出入口の名称を採録した。
合計 197 出入口（35 駅 + 新駅 36/37 のうち読み取れた範囲）。

## 座標が「推定値」である理由（重要）

調査の結果、**公式サイトも公式オープンデータも出入口の緯度経度を公表していない**。
- 駅ページが提供するのは駅立体図（屋内模式図の画像。縮尺・方位の保証なし）と
  駅周辺地図（Google マップへのリンク）のみ。
- 公式オープンデータ（`/subway/about/material.php`）は乗車人員・時刻表のみ。

そのため座標は次の方針で**近似**する（`_estimate_entrance_coord`）:
- 親駅の既知座標を基準に、出入口名に方角語（北/南/東/西/中央）があればその方向へ約 60m ずらす。
- 方角語が無い連番出入口（例「1番出口」）は、駅を中心に放射状へ等間隔で配置する。
- 同方向の複数出入口が完全に重ならないよう連番で微小に散らす。

→ **位置は概ね親駅周辺に正しく置かれるが、各出入口の正確な位置ではない。**
利用前に地図照合（手動確認）を推奨。より正確な座標が得られれば
`STATION_ENTRANCES` を方角語付き、または `AIRPORT_ENTRANCES` 形式の実測座標へ差し替える。

### 例外: 福岡空港(id 13)

福岡空港駅の立体図画像は未公開（404）だったため、出入口名・座標とも本人作成の旧フィード
（git `0e19136`「各駅の各ホーム，各出入口の緯度・経度を登録しました」, 2018年版）から
**実測値**を採録した（`AIRPORT_ENTRANCES`）。

### 例外: 博多（複合駅）

博多は空港線博多（id 11）と七隈線博多（id 37）を別駅としてモデル化している
（[`hakata-nanakuma-station.md`](hakata-nanakuma-station.md)）。物理的には一体の複合駅だが、
出入口は**西側コンコース（七隈線寄り）を 37**、**東/中央側を 11** に割り当て、二重計上を避けた。

## 参考: 旧フィード(2018年版)との関係

git 履歴 `0e19136` に 2018 年版の出入口 198 件（座標付き、本人作成）が残っており、
出入口名・配置のクロスチェック資料として用いた。本実装の一次採用は「公式立体図の名称＋推定座標」
だが、福岡空港のように公式画像が無い駅では旧フィードの実測座標を採用している。

## スコープ外

- 出入口名の多言語訳（`translations.txt`）。駅名（`stops.stop_name`）の訳は既存のままで、
  出入口名そのものの訳は今回追加しない。
- `pathways.txt`（出入口↔ホームの通路・所要時間）。別 Issue。
